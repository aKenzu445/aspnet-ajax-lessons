# Занятие 7 — заметки и выводы

## Задача 1. Медленная обратная связь (только серверная проверка)

Классическая форма на `/Tasks` отправлена с **пустым** названием:
```
POST /Tasks (NewTask.Title = "") → 200, сервер вернул ВСЮ страницу заново (≈15,5 КБ HTML)
→ на странице: «Название обязательно»
```
Во вкладке **Network** виден полноценный запрос `POST /Tasks` и ответ с HTML всей страницы, страница перезагружается.

**Вывод:** сейчас ошибка появляется **только после** отправки формы на сервер и получения ответа (полный HTTP round-trip). **Клиентской проверки нет вообще.** В HTML формы уже есть атрибуты `data-val-required="Название обязательно"` (их сгенерировал `asp-for` по `[Required]`), но на странице **не подключены** скрипты, которые умеют их читать (`jquery.validate`: 0 совпадений в HTML). Пользователь каждый раз ждёт ответа сервера и видит, как мигает страница.

## Задачи 2–3. Подключение unobtrusive-валидации и проверка

- Создан `Pages/Shared/_ValidationScriptsPartial.cshtml`: три скрипта с CDN (`jquery`, `jquery.validate`, `jquery.validate.unobtrusive`).
- Подключён в секции `Scripts` страниц `/Tasks` и `/Tasks/Edit`: `<partial name="_ValidationScriptsPartial" />`.
- View Page Source: у полей `asp-for="NewTask.Title"` / `asp-for="Task.Title"` есть
  `data-val="true" data-val-required="Название обязательно" data-val-length="..." data-val-length-max="100"`.
  Эти атрибуты сгенерированы **автоматически** из `[Required]` и `[StringLength]` на `TaskItem.Title`.

**Задача 3, проверка в браузере:** пустое название → «Добавить (с перезагрузкой)»:
- сообщение «Название обязательно» появляется **мгновенно**, поле подсвечено красным (класс `input-validation-error`);
- страница **не** перезагружалась, во вкладке **Network** после клика **нет ни одного запроса** (последние запросы — загрузка самой страницы).

| | Задача 1 (без скриптов) | Задача 3 (unobtrusive) |
|---|---|---|
| Запрос на сервер | `POST /Tasks` → 200, вся страница заново | **не отправляется** |
| Когда видна ошибка | после ответа сервера | сразу после клика |
| Перезагрузка | да | нет |

## Задача 4. Минимальная длина — без единой правки JS

Атрибут изменён на `[StringLength(100, MinimumLength = 3, ErrorMessage = "От 3 до 100 символов")]`. Больше ничего не менялось.

Сгенерированное поле теперь содержит `data-val-length-min="3"` и `data-val-length="От 3 до 100 символов"`. Unobtrusive-скрипт подхватил новое правило **сам**:
- «аб» (2 символа) → мгновенно «От 3 до 100 символов», запрос не отправлен;
- «абв» (3 символа) → форма отправлена, «Задача успешно добавлена!».

`MinimumLength` не влияет на структуру базы, поэтому новая миграция не нужна. Ограничивается только длина, которую можно ввести.

## Задача 5. Собственный атрибут `[NoForbiddenWords]`

`Validation/NoForbiddenWordsAttribute.cs`: наследник `ValidationAttribute`, в `IsValid` проверка `text.Contains("тест", StringComparison.OrdinalIgnoreCase)`. Применён к `TaskItem.Title`.

**Проверка:** классическая форма «Тестовая задача» → сервер отклонил (200, страница с ошибкой «Название не должно содержать слово 'тест'»), в базе такой задачи нет.

## Задача 6. Ограничение: собственный атрибут не работает на клиенте «из коробки»

**Что видно во вкладке Network** при «Тестовая задача» → «Добавить»:
```
POST http://localhost:5107/Tasks → 200 OK     ← запрос УШЁЛ на сервер (в отличие от задачи 3)
```
Ошибка появилась только после перезагрузки страницы.

**Причина (теория 7.4):** для `[Required]` и `[StringLength]` тег-хелпер генерирует атрибуты `data-val-required`, `data-val-length`, и у `jquery.validate.unobtrusive` есть готовые JS-адаптеры для них. Для собственного `[NoForbiddenWords]` **ни атрибута `data-val-*`, ни JS-адаптера нет** (в HTML поля 0 упоминаний). Браузер ничего не знает об этом правиле, и оно проверяется только на сервере.

**Улучшение UX:** добавлена ручная JS-проверка (`wwwroot/js/title-checks.js`, функция `attachForbiddenWordsCheck`). Перед отправкой классической формы она проверяет `input.value.toLowerCase().includes("тест")`. Если слово есть, показывает ошибку в том же `<span asp-validation-for>` и отменяет отправку `event.preventDefault()`. **Серверная проверка `[NoForbiddenWords]` осталась** как обязательный рубеж: JS можно отключить или обойти.

**После доработки (проверено в браузере):** «Тестовая задача» на `/Tasks` и «ТЕСТ ещё раз» на `/Tasks/Edit/1` → ошибка «Название не должно содержать слово 'тест'» появляется **мгновенно**, страница не перезагружается, `POST` не отправляется.

Техническая деталь: сначала ошибка мигала и тут же пропадала. Сразу после нашего обработчика `submit` срабатывает `jquery.validate`. По **его** правилам поле корректное, и он очищал `<span>`. Поэтому сообщение выводится через `setTimeout(..., 0)`, то есть уже **после** работы `jquery.validate`. Правильное «промышленное» решение — написать JS-адаптер для атрибута (`$.validator.addMethod` + `$.validator.unobtrusive.adapters`). Это выходит за рамки занятия (теория 7.4).

## Задача 7. Minimal API не проверяет DataAnnotations автоматически

**Воспроизведение (запросы напрямую к API, в обход сайта):**
```
POST /api/tasks {"title":""}                → 400 (ручная проверка IsNullOrWhiteSpace из занятия 1)
POST /api/tasks {"title":"Тестовая задача"} → 201 ❌ создана, хотя [NoForbiddenWords] запрещает
POST /api/tasks {"title":"аб"}              → 201 ❌ создана, хотя минимум 3 символа
POST /api/tasks {"title":"Нормальная","category":"Хобби"} → 201 ❌ хотя [AllowedCategory]
```
(Пустое название получало 400 только благодаря ручной проверке занятия 1. Атрибуты в Minimal API сами не срабатывают: `ModelState` есть только в Razor Pages/MVC.)

**Исправление** — явная проверка тех же атрибутов в `POST /api/tasks`:
```csharp
var results = new List<ValidationResult>();
bool isValid = Validator.TryValidateObject(created, new ValidationContext(created), results, validateAllProperties: true);
if (!isValid)
    return Results.BadRequest(new { Errors = results.Select(r => r.ErrorMessage) });
```
`validateAllProperties: true` проверяет **все** атрибуты (без этого флага — только `[Required]`).

**После исправления:**
```
{"title":""}                → 400 {"errors":["Название обязательно"]}
{"title":"Тестовая задача"} → 400 {"errors":["Название не должно содержать слово 'тест'"]}
{"title":"аб"}              → 400 {"errors":["От 3 до 100 символов"]}
{"category":"Хобби", ...}   → 400 {"errors":["Выберите категорию из списка: Работа, Учёба, Личное, Спорт"]}
{"title":"Корректная задача"} → 201
```
Minimal API и Razor Pages используют **одни и те же правила** из класса `TaskItem`, без дублирования.

## Задача 8. Клиентская проверка перед AJAX-запросом (defense in depth)

- **Первый рубеж (браузер):** в обработчике кнопки «Добавить задачу» перед `fetch` вызывается `findTitleProblem(input.value)` (`wwwroot/js/title-checks.js`): пусто → «Название обязательно», короче 3 → «От 3 до 100 символов», «тест» → запрет. Если есть ошибка, она показывается сразу, и `fetch` **не выполняется**.
- **Второй рубеж (сервер):** обработка ответа `!response.ok` оставлена. Теперь она понимает и `{ "errors": [...] }`.

**Проверка в браузере (счётчик реальных запросов к `/api/tasks`):**

| Ввод | Сообщение | Запросов |
|---|---|---|
| `""` | Название обязательно | 0 |
| `"аб"` | От 3 до 100 символов | 0 |
| `"Тестовая задача"` | Название не должно содержать слово 'тест' | 0 |
| `"   ок   "` | От 3 до 100 символов (после `trim()` осталось 2 символа) | 0 |
| «Тестовая задача» с **отключённой** клиентской проверкой | Название не должно содержать слово 'тест' | **1** → сервер ответил 400 |
| «Нормальное название» | Задача №11 добавлена | 2 (POST + GET списка) |

Временное отключение клиентской проверки показало: **сервер всё равно защищает данные** (400 из задачи 7). Клиентская проверка нужна для мгновенного UX, серверная — для защиты.

## Задача 9. Валидация уровня модели и `asp-validation-summary`

**Правило:** если `IsDone == true`, название обязательно. Ошибка относится **ко всей форме**, а не к одному полю.

`EditModel.OnPostAsync`:
```csharp
if (Task.IsDone && string.IsNullOrWhiteSpace(Task.Title))
    ModelState.AddModelError("", "Нельзя отметить выполненной задачу без названия");   // "" — ошибка модели
if (!ModelState.IsValid) { SetDescription(); return Page(); }
```
Важный нюанс: проверка стоит **до** `return Page()`. При пустом `Title` модель уже невалидна из-за `[Required]`. Если бы ручная проверка шла после `if (!ModelState.IsValid) return Page();`, до неё выполнение просто не дошло бы.

В форме: `<div asp-validation-summary="All" class="validation-summary"></div>`.
- `asp-validation-for="Task.Title"` — ошибка **рядом с одним полем**;
- `asp-validation-summary="All"` — **сводка всех** ошибок, в том числе с ключом `""` (уровня модели). Вариант `"ModelOnly"` показывал бы только ошибки модели.

**Проверка (сервер, curl):** `Title = ""`, `IsDone = true` → 200, сводка:
```
• Название обязательно
• Нельзя отметить выполненной задачу без названия
```
задача в базе не изменилась.

**В браузере:** клиентская валидация не пустила бы форму с пустым названием на сервер. Поэтому то же правило продублировано маленьким JS (только для удобства), и сводка показывает обе ошибки **мгновенно**.

## Задача 10. Пограничный случай: пробелы

**Воспроизведение (до исправления):**

| Ввод | Классическая форма | API | Редактирование |
|---|---|---|---|
| `"   "` (только пробелы) | 200, «Название обязательно» ✅ | 400 «Название обязательно» ✅ | — |
| `"  аб  "` | **302 — сохранено «аб» (2 символа!)** ❌ | 400 «От 3 до 100 символов» ✅ | **302 — сохранено «  аб  » С ПРОБЕЛАМИ** ❌ |

Строку **только из пробелов** уже отклонял `[Required]`: в современном .NET он считает пустой строку из одних пробелов (`string.IsNullOrWhiteSpace`). Описанный в задании баг в чистом виде не воспроизвёлся. Но нашлась **настоящая дыра того же рода**: атрибуты проверяли значение **до** обрезки пробелов. `"  аб  "` — это 6 символов, `[StringLength(MinimumLength = 3)]` пропускал их. Потом форма добавления делала `Trim()` и сохраняла «аб», а форма редактирования вообще не обрезала пробелы. В API такой проблемы не было: там `Trim()` выполнялся **до** `TryValidateObject`.

**Исправление (в обоих местах на сервере):**
- **Razor Pages** (`TasksModel.OnPostAsync`, `EditModel.OnPostAsync`): сначала `Title = Title.Trim()`, затем `ModelState.ClearValidationState(...)` (забыть старый результат), затем собственная проверка `if (string.IsNullOrWhiteSpace(Title))` → ошибка «Название обязательно», иначе `TryValidateModel(...)` проверяет все атрибуты **заново** по обрезанному значению.
- **Minimal API** (`POST /api/tasks`): `Title = request.Title?.Trim()` до проверки, явная проверка `IsNullOrWhiteSpace` → 400 `{"errors":["Название обязательно"]}`, затем `TryValidateObject`.
- **Клиент** (опционально): `findTitleProblem()` проверяет `value.trim().length`.

**После исправления:**
```
Классическая форма "   "            → 200 «Название обязательно»
Классическая форма "  аб  "         → 200 «От 3 до 100 символов»
Классическая форма "  Нормальная  " → 302, в базе [Нормальная] без пробелов
API "   "                           → 400 {"errors":["Название обязательно"]}
Редактирование "  аб  "             → 200 «От 3 до 100 символов»
Редактирование "  Изучить валидацию  " → 302, в базе [Изучить валидацию]
```

- **Razor Pages:** поле срока в классической форме добавления (`asp-for="NewTask.DueDate"`) и на странице редактирования (`asp-for="Task.DueDate"`). Проверка идёт через `ModelState` (атрибут срабатывает сам).
