# Занятие 3 — заметки и выводы

## Задача 1. Адрес страницы без `.cshtml`
`Pages/Test.cshtml` открывается по адресу **`/Test`**. Маршрут Razor Pages строится из пути файла внутри папки `Pages` без расширения: `Pages/Tasks.cshtml` → `/Tasks`, `Pages/Index.cshtml` → `/`. Свой адрес можно задать в директиве: `@page "/crash-test-page"`.

## Задача 2. Почему JS не пришлось менять
HTML и `<script>` перенесены из `wwwroot/index.html` в `Pages/Index.cshtml` без изменений, и все `fetch("/api/...")` работают. Браузеру всё равно, откуда пришёл HTML: со статического файла или сгенерированный Razor. В обоих случаях он получает обычный HTML с `<script>`. Старый `wwwroot/index.html` удалён, `UseDefaultFiles()` убран. Теперь `/` обслуживает Razor-страница, в `wwwroot` остались только CSS.

## Задача 3. Где лежат `_ViewStart` и `_ViewImports`
В таблице теории они указаны в `Pages/Shared/`, но в проекте лежат в **`Pages/`**. Эти файлы действуют на страницы **своей папки и всех вложенных**. Из `Pages/Shared` они применились бы только к файлам внутри `Shared`, а `Index.cshtml` и `Tasks.cshtml` остались бы без layout. `_Layout.cshtml` лежит в `Pages/Shared/`: там Razor ищет общие layout и partial по имени.

Проверка: если изменить текст «Task Manager» в `_Layout.cshtml`, он меняется на **всех** страницах, хотя `Index.cshtml` не трогали.

## Задача 5. Серверная отрисовка (SSR)
Список задач на `/Tasks` приходит **внутри HTML** страницы: его формирует `TasksModel.OnGet()` + `@foreach`. Проверка без JavaScript: `curl http://localhost:5103/Tasks` (curl не выполняет JS) возвращает HTML, где уже есть все `<li>` с задачами. Если в браузере отключить JS, задачи видны, а добавлять и удалять их нельзя (эти кнопки работают через AJAX).

## Задача 6. Ограничение partial view
`_TaskItem.cshtml` выполняется **на сервере** при генерации страницы. JavaScript в браузере, добавляя задачу через AJAX, не может «вызвать» `.cshtml`: у него есть только JSON от `/api/tasks`. Поэтому та же разметка строки продублирована в JS (функция `taskToHtml`). Это граница между **серверным** (Razor) и **клиентским** (JS) рендерингом. При изменении разметки править нужно оба места. Визуально строки одинаковые.

## Задача 7. Секции
`@RenderSection("Scripts", required: false)` в layout выводит секцию `@section Scripts { ... }` конкретной страницы. Проверка через «Просмотр кода страницы»: на `/Tasks` нет кода калькулятора (`sumBtn`), на `/` нет `loadTasks`.

## Задача 8. Активный пункт меню
`ViewContext.RouteData.Values["page"]` содержит путь текущей Razor-страницы (`"/Index"`, `"/Tasks"`, `"/About"`). Функция `ActiveClass(...)` в `_Layout.cshtml` через `if` возвращает `"active"` для совпадающего пункта.

## Задача 9. Две разные обработки ошибок одновременно
```
app.UseExceptionHandler("/Error");   // 1-й: для страниц сайта → HTML Pages/Error.cshtml
app.Use(... try/catch ... when (Path начинается с /api) ...)  // 2-й: для API → JSON
```
- `GET /api/crash-test` → ошибку ловит наш middleware (фильтр `when` пропускает только `/api`) → **500 + JSON** `{"error":"Внутренняя ошибка сервера"}`.
- `GET /crash-test-page` → фильтр `when` не срабатывает, исключение «всплывает» к `UseExceptionHandler`. Тот повторно выполняет запрос по адресу `/Error` → **500 + HTML-страница** «Что-то пошло не так».

## Дополнительно (не задача, а изменение)
- **Кириллица в исходнике страницы:** Razor по умолчанию превращает русские буквы в коды `&#x418;`. Добавлена настройка `WebEncoderOptions` (`UnicodeRanges.All`), и текст в «Просмотре кода» читается нормально. Символы `< > &` по-прежнему экранируются (проверено задачей с названием `<b>жирный</b>`).
- **Rate limiting (ДЗ занятия 2):** лимит вынесен в `appsettings.json` → `RateLimiting` и увеличен до 30 запросов за 10 секунд. Иначе обычная работа со списком (добавление = POST + GET) быстро упиралась в 429. В папке `Lesson02` остался исходный лимит 5 за 10 секунд.
