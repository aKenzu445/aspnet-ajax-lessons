# Занятие 1. Веб-сервер на ASP.NET Core и первые AJAX-запросы

Проект **Lesson1.WebServer** — сервер Task Manager. Это состояние проекта **после занятия 1**.

## Как запустить
1. В Rider открой `AjaxLessons.slnx` (корень репозитория).
2. В панели Solution раскрой папку **Занятие 1**, правый клик по проекту **Lesson1.WebServer** → **Run** (или выбери его в списке конфигураций вверху справа и нажми ▶).
3. Сервер запустится на **http://localhost:5101**, откроется браузер.
4. Запросы для проверки без браузера: файл [`requests.http`](requests.http) (зелёная стрелка слева от запроса).

Порт записан в `Properties/launchSettings.json` → `"applicationUrl": "http://localhost:5101"` (это требование задачи 1, п. 4).

## Пояснения к задачам («зафиксировать письменно»)

**Задача 4. Зачем `app.UseStaticFiles()`.** Это middleware, которое отдаёт файлы из папки `wwwroot` «как есть». Без него запрос `/index.html` вернул бы 404: сервер не знал бы, что есть такая папка. `UseDefaultFiles()` дополнительно подставляет `index.html` при запросе корня `/`.

**Задача 5. Что происходит без параметра `a` или `b`.** Параметры объявлены как `double a, double b`, поэтому они **обязательные**. Если параметра нет (`/api/sum?a=5`) или это не число (`a=abc`), Minimal API **сам** возвращает **400 Bad Request** ещё до запуска нашего кода. Сервер не падает, но ответ — технический текст исключения. Поэтому в задаче 7 параметры сделаны `string?` и проверяются вручную через `double.TryParse`, чтобы вернуть понятный JSON `{ "error": "..." }`.

**Задача 6. Разница с задачей 5.** В задаче 5 данные передаются **в адресе** (query string, `?a=5&b=3`), это типично для GET. В задаче 6 данные передаются **в теле запроса** в формате JSON. Нужно указать заголовок `Content-Type: application/json` и тело `JSON.stringify({...})`. ASP.NET Core видит параметр сложного типа (`EchoRequest`) и читает его из тела.

**Задача 9. Какой подход выбран для обновления списка.** После успешного `POST` страница **заново запрашивает весь список** (`GET /api/tasks`). Почему: сервер — единственный источник правды. На экране точно те данные, что сохранены на сервере, и видны изменения других пользователей. Минус — лишний запрос, но для маленького списка это неважно. Альтернатива — добавить `<li>` прямо из ответа сервера: быстрее, но список может разойтись с сервером.

**Коды ответов, которые используются:** 200 OK, 201 Created (задача создана), 400 Bad Request (ошибка в данных), 404 Not Found (задачи нет).
