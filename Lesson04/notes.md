# Занятие 4 — заметки и выводы

## Задача 1. «Пустой» заголовок страницы

**До:** в `_Layout.cshtml` (занятие 3) уже было `<title>@ViewData["Title"] — Task Manager</title>`, но значение никто не задавал. View Page Source:
```
/      → <title> — Task Manager</title>
/Tasks → <title> — Task Manager</title>
```
`ViewData["Title"]` было `null`, и Razor вывел пустоту перед тире.

**После:** в начале страниц добавлен блок `@{ ViewData["Title"] = "..."; }`:
```
/      → <title>Главная — Task Manager</title>
/Tasks → <title>Задачи — Task Manager</title>
```
**Почему это работает:** `ViewData` — словарь (`Dictionary<string, object>`) одного запроса, общий для страницы и её layout. Страница выполняется **раньше** layout, поэтому значение, записанное в странице, layout уже видит.

## Задача 2. ViewBag и ViewData — одно и то же

**Эксперимент:** в `TasksModel.OnGet()` значение записано через **ViewData**:
```csharp
ViewData["PageDescription"] = "Здесь вы можете управлять своими задачами";
```
а в `Tasks.cshtml` прочитано через **ViewBag**:
```cshtml
<p class="page-description">@ViewBag.PageDescription</p>
```
**Результат:** на странице выведено «Здесь вы можете управлять своими задачами».

**Почему сработало:** `ViewBag` — не отдельное хранилище, а **динамическая обёртка** (`dynamic`) над тем же словарём `ViewData`. `ViewBag.PageDescription` — это просто другой синтаксис для `ViewData["PageDescription"]`. Отличия:
- `ViewData["Ключ"]` — доступ по строковому ключу, при чтении нужно приведение типа: `(string)ViewData["Title"]`;
- `ViewBag.Ключ` — короче и без приведения типа (`dynamic` проверяется только во время выполнения).
- **Оба** слабо типизированы: опечатку в ключе (`ViewData["Titel"]` или `ViewBag.Titel`) компилятор **не найдёт**, будет просто `null`.

**Что выбрать в проекте:** для мелочей (заголовок, описание) подходит любой. Достаточно договориться об одном стиле. Для структурированных данных нужна строго типизированная модель (`Model`, см. задачи 6–7).
