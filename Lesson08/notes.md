# Занятие 8 — заметки и выводы

## Задача 1. Проблемы категорий в виде строки

В проекте уже есть «быстрое» решение из прошлых домашек: `TaskItem.Category` — **строка** (`string?`, ДЗ занятия 5), плюс список допустимых значений `TaskCategories.All` и атрибут `[AllowedCategory]` (ДЗ занятия 6). Так делать **плохо**:

1. **Опечатки и разное написание.** «Работа», «работа», «Робота» для базы — три **разные** категории. Атрибут `[AllowedCategory]` частично спасал, но список зашит в код. Чтобы добавить категорию, нужно менять код и пересобирать проект.
2. **Нельзя централизованно переименовать.** Чтобы «Учёба» стала «Обучение», нужно обновить строку **в каждой** задаче (`UPDATE Tasks SET Category = ...` по всем строкам). Если что-то пропустить, данные станут несогласованными.
3. **Нет списка «все категории».** Получить его можно только перебором всех задач (`Select(t => t.Category).Distinct()`, как в фильтре ДЗ занятия 5). Категория без задач вообще «не существует», её нельзя создать заранее.
4. **Лишнее место и медленный поиск:** одна и та же строка хранится в каждой задаче, а сравнивать строки дольше, чем числа.

**Вывод:** категориям нужна **отдельная таблица** `Categories (Id, Name)` и связь «один-ко-многим» с задачами через **внешний ключ** `Tasks.CategoryId → Categories.Id`:
- имя категории хранится **один раз**. Переименование — одно изменение в одной строке;
- задача ссылается на категорию **по номеру** (`CategoryId`). База сама не даст сослаться на несуществующую категорию (ограничение внешнего ключа);
- список категорий — это просто `SELECT * FROM Categories`, и новые категории добавляются без изменения кода (страница `/Categories`, задача 4).
